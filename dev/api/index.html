RestClient.@globalconfig — Macro
@globalconfig config [auth=scheme | auth=(scheme, policy)] [format=fmt] [supertype=T]

Define globalconfig for the current module as config, and optionally module-wide authentication, format and supertype defaults for its endpoints.

This avoids having to write the slightly awkward RestClient.globalconfig(::Val{@__MODULE__}) = config by hand. Similarly, the optional auth clause defines a RestClient.globalauthdefault(::Val{@__MODULE__}) method. The auth argument may take one of two forms:

  • auth = scheme: the AuthScheme endpoints in this module use (e.g. BearerAuth()); the request's key is applied to it. With no policy given, the policy is :off — declare the scheme, but send it only where an endpoint opts in.
  • auth = (scheme, policy): also set the authpolicy, one of:
    • :off — never send auth (the scheme is declared but unused here);
    • :optional — send the key if one is set, but do not require it;
    • :required — send the key, and reject a request that has none before sending.

The format clause sets the AbstractFormat of values that have none of their own, such as a Vector{String} or Dict{String, Any} result, or a String to decode as JSON, in place of RawFormat. Bytes (Vector{UInt8}, IO) stay raw. It may be a format, such as JSONFormat(), or the shorthand :json or :xml. A dataformat method for an endpoint and type still takes precedence.

The supertype clause gives every @endpoint in the module that declares no supertype of its own this one, an abstract subtype of AbstractEndpoint for behaviour the API's endpoints share (see AbstractEndpoint for which methods can be shared). Since a struct's supertype is fixed when it is defined, @globalconfig must come before the endpoints it applies to.

See also: globalconfig, RequestConfig, authscheme.

Examples

@globalconfig RequestConfig("https://api.example.com")
# Send a Bearer token on every endpoint when a key is set:
@globalconfig RequestConfig("https://api.example.com") auth=(BearerAuth(), :optional)
# Require a key on every endpoint (mark public ones `:noauth`):
@globalconfig RequestConfig("https://api.example.com") auth=(BearerAuth(), :required)
# Read and send plain values (e.g. a `Vector{String}`) as JSON:
@globalconfig RequestConfig("https://api.example.com") format=:json

RestClient.@endpoint — Macro
@endpoint struct ... end
@endpoint [func(...)] -> [struct ... end] -> [payload] -> url -> [resulttype]

Generate an endpoint implementation from a concise shorthand form.

This macro can be applied to either an endpoint struct definition or a chain of arrow forms joined by ->. These arrow forms represent the flow of information:

  1. The creation of a request, from a function call (optional)
  2. The struct used to represent the request data (optional, autogenerated from the function call)
  3. Any payload provided with the request (if applicable)
  4. The page URL the request is directed to (relative to the base URL)
  5. The type that the response is expected to correspond to

For a basic API, this can be as simple as:

@endpoint israining(city::String) -> "checkrain/{city}" -> Bool

Using this macro is equivalent to implementing a plain struct, along with these endpoint methods:

  • urlpath
  • parameters (if needed)
  • payload (optionally)
  • responsetype

urlpath, parameters and payload are defined in their two-argument form, taking the request's RequestConfig first, so they take precedence over any method on a supertype. Parameters every endpoint of an API needs are instead defined for the API's type, and are added to those generated (see parameters).

In our @endpoint israining() ... example, in addition to defining the israining function and an (implicit) IsrainingEndpoint struct, the macro will generate the implementations urlpath(rain::IsrainingEndpoint) = "checkrain/$(rain.city)" and responsetype(::IsrainingEndpoint) = Bool.

In addition to applying @endpoint to a sequence of arrow forms you can also apply it to a struct that starts with a special line of non-struct arrows.

For instance, our israining() example could be alternatively written as:

@endpoint struct IsrainingEndpoint
    israining(city) -> "checkrain/{city}" -> Bool
    city::String
end

This generates the exact same code as the initial example form.

For more information on how each component of the shorthand form is interpreted, as well as more complex examples, see the extended help section.

See also: urlpath, parameters, payload, responsetype, Request, globalconfig, @globalconfig.

Extended help

Function forms

Should you choose to include a function call as the first arrow form, a function definition with a matching signature will be generated. This requires globalconfig(::Val{@__MODULE__}) to be defined, as is done by @globalconfig.

Without a struct form, the arguments of the function will be used to generate a struct named after the function, with each _-separated word capitalised and joined, and Endpoint appended (getUserInfo gives GetUserInfoEndpoint, and list_repos gives ListReposEndpoint), and populate its fields.

With a struct form, all arguments that match a field name will inherit the field's type and default value, though a positional argument followed by a required one stays required. All the fields of the struct not present in the signature will be added as keyword arguments, with Union{..., Nothing} typed fields defaulting to nothing. This makes function forms an easy way to prescribe positional, mandatory arguments with the flexibility to fully specify the endpoint with keyword arguments.

A docstring on an @endpoint with a function form documents the function, and the struct is given a docstring that points to it. Without a function form, the docstring documents the struct.

"""
    dothing(input) -> Output

Do the thing to `input`.
"""
@endpoint dothing(input::Foo) -> "thing/{input}" -> Output

Authentication markers

An @endpoint can start with a marker setting its authpolicy in place of the API's default: :auth requires the request's key, :authoption sends it if one is set, and :noauth never sends it.

@endpoint :auth whoami() -> "me" -> User

Struct forms

The endpoint struct can be given explicitly, or generated from the function call. For instance, the function call api(target::String; count::Int=1) will generate this struct form:

@kwdef struct ApiEndpoint
    target::String
    count::Int = 1
end

When autogenerated, or not specified, the endpoint's supertype is that set by @globalconfig's supertype option, or else AbstractEndpoint. What a request returns follows from its result type alone (see AbstractEndpoint), so any supertype, such as one shared across an API, works for any result.

If @endpoint is directly applied to a struct, the first line of the struct is removed and parsed as a series of arrow forms. That line is always taken as the endpoint's, so a string there is its URL; a docstring for the first field goes after it.

@endpoint struct ApiEndpoint
    api(target; count) -> ...
    target::String
    count::Int = 1
end

This makes no difference to the generated code; the explicit struct form can be clearer for more complex endpoints.

An endpoint struct can also be copied with some of its fields changed, as ApiEndpoint(endpoint; count = 2), such as to give the next page in nextpage.

Payload forms

HTTP methods like :post, :put, and :patch include a content payload (also referred to as the request body). The payload can be specified with a payload form that names a field of the endpoint struct, names a global variable, or is an expression evaluated to generate the payload value (with the current endpoint available through the anaphoric variable self). Fields can be named directly within the expression too, as in -> Upload(content) ->; a field sharing its name with a global variable must be written as self.field.

Unless otherwise specified, an endpoint that includes a payload is assumed to be a :post request (:get without).

@endpoint upload(content::String) -> content -> "create" -> Status

This is equivalent to the explicit HTTP method form:

@endpoint upload(content::String) -> content -> :post("create") -> Status

In this example content is a String, and so a :post request is made to "$BASEURL/create" with content as the payload/body. More complex types are encoded by writepayload, according to their dataformat.

URL forms

The endpoint URL is represented by a string, relative to the base URL of the API (a leading / is stripped). Such paths usually consist of a path component, and optionally a query component.

"some/path/for/my/api?query=param&other=value"

Within this endpoint URL, you can include references to fields of the struct (or global variables) by surrounding them with curly braces.

"page/{somefield}?param={another}&{globalvar}=7"

Parameters with a value of nothing are omitted from the query string, a collection (a Vector, Tuple, or Set) is sent as one parameter per element (?tag=a&tag=b), and other values are converted with string. A component without a value (?verbose) is sent as written. In the path, nothing is an error rather than omitted.

string sends a Bool as true or false, which some APIs read as set whatever its value; for those, send {Int(flag)}. An API that wants a list as one comma-joined parameter (?tags=a,b) can be given one with {join(tags, ',')}.

For convenience, a parameter by the same name as the field can be referred to by the field name alone (e.g. ?{var} instead of ?var={var}).

In more complex cases, arbitrary Julia code can be included in the curly braces. This code will be evaluated with the endpoint value bound to the anaphoric variable self as well as config for the request configuration. Fields can be named directly in the code too, as in payload forms.

"page/{if self.new \"new\" else \"fetch\" end}/{id}"

If that's not enough, you can also use an arbitrary expression in place of the endpoint string:

if self.create "pages/create/" else "pages/fetch/id/" * self.id end

When using expression instead of a string though, curly braces are not interpreted as field references.

Specifying the HTTP method

By default, it is guessed whether the API expects a :get or :post request based on the presence or absence of an input form. This can be explicitly specified by wrapping the URL form in an HTTP method symbol, for example:

:head("existence/{entity}")

A :query endpoint sends its payload as a QUERY request: like a :post, but safe and idempotent, so its responses are cached like a :get's (keyed on the payload too). The payload is required, since it is the query.

@endpoint search(filter::Filter) -> filter -> :query("items") -> Vector{Item}

Response type forms

It is sensible to parse the raw response into a more informative Julia representation. The response type specifies what type the response can be parsed to, which is performed by interpretresponse according to dataformat.

Often the result type will name a struct defined with [@jsondef].

The result type may be omitted when the response body is of no interest, which is equivalent to giving Nothing: the body is discarded, the response is never cached, and the endpoint returns nothing.

@endpoint announce(msg::String) -> msg -> :post("events")

When the URL is an expression rather than a string (or :method(url) form), the result type cannot be told apart from it, so must be given explicitly.

The parsed result can be reinterpreted into another form with postprocess. By default, ListResponse-type responses are restructured into a List to facilitate paging.

Examples

@endpoint struct ShuffleEndpoint
    "deck/{deck}/shuffle?remaining={ifelse(self.remaining, '1', '0')}" -> Deck
    deck::String
    remaining::Bool
end

This is equivalent to defining the struct by itself, and then separately defining the three basic endpoint methods.

struct ShuffleEndpoint
    deck::String
    remaining::Bool
end

RestClient.urlpath(shuf::ShuffleEndpoint) =
    "deck/$(shuf.deck)/shuffle"
RestClient.parameters(shuf::ShuffleEndpoint) =
    ["remaining" => ifelse(shuf.remaining, "1", "0")]
RestClient.responsetype(shuf::ShuffleEndpoint) = Deck

RestClient.@jsondef — Macro
@jsondef [:noshow] [kind] struct ... end

Define a struct that can be read from and written as JSON.

This macro conveniently combines the following pieces:

  • @kwdef to define keyword constructors for the struct.
  • Custom Base.show method to show the struct with keyword arguments, omitting default values (suppress with the :noshow option).
  • Registration of the JSON field-name mapping with JSON.jl.
  • RestClient.dataformat to declare that this struct is JSON-formatted.

Note the name."json_field" syntax demonstrated in the examples, that allows for declaration of the JSON object key that should be mapped to the field. The key is one name, not a path into nested objects; model those with a nested type. Keys of the JSON object that no field names are ignored. A field typed Union{…, Nothing} defaults to nothing. A field that is nothing is left out of the JSON written, as most APIs read a missing key as "not given"; to send an explicit null, type the field Union{Nothing, JSON.Null} and set it to JSON.Null().

The optional kind argument selects the JSON representation, one of Struct (the default), Dict, Array, Vector, Nothing, and String. For String, the user must define Base.string and a T(::AbstractString) constructor. A number or boolean representation needs user-defined StructUtils.lift / StructUtils.lower methods instead.

For an open-ended JSON object or array, a struct with a single field of kind Dict or Array/Vector reads the whole object or array into that field, whether it is the response itself or nested within another struct. A container kind with more fields is read and written as a struct of its fields, like Struct.

@jsondef Dict struct Translations
    entries::Dict{String, String}   # {"en": "Hello", "fr": "Bonjour"} → Translations(...)
end
Soft JSON dependency

This macro is implemented in a package extension, and so requires JSON to be loaded before it can be used.

Examples

@jsondef struct DocumentStatus
    exists::Bool  # Required, goes by 'exists' in JSON too
    status."document_status"::Union{String, Nothing} = nothing
    url."document_url"::Union{String, Nothing} = nothing
    age::Int = 0  # Known as 'age' in JSON too, defaults to 0
end

RestClient.@xmldef — Macro
@xmldef struct ... end

Define a struct that can be used with XML.

This macro conveniently combines the following pieces:

  • XML deserialization
  • @kwdef to define keyword constructors for the struct.
  • RestClient.dataformat to declare that this struct is XML-formatted.

Note the name."xpath" syntax demonstrated in the examples, that allows for declaration of the (simple) XPath that should be used to extract the field. A field without one reads the child element named after it, so title::String reads <title>. The subset of supported XPath components are:

  • nodetag to extract all immediate children with a given tag name
  • . to extract the node itself, such as its whole text, or a type read from the same element
  • relative/node/paths
  • * to extract all children
  • text() to extract a node's own text, without that of elements within it
  • @attr to extract the value of an attribute
  • nodetag[i] to extract the i-th child of type nodetag
  • nodetag[last()] to extract the last child of type nodetag

A text or number field read from an element takes all the text within it, so <title><i>E. coli</i> Nissle</title> gives "E. coli Nissle" where title/text() gives " Nissle".

A field whose XPath matches nothing takes its default value. Unlike plain @kwdef, a default can't refer to other fields. A Vector field takes every match through every step of its path, so a/@b gives the b of each a. Other fields need each step before the last to match one element; at the last, a Union{…, Nothing} field takes the first of several, and any other field requires exactly one.

Soft XML dependency

This macro is implemented in a package extension, and so requires XML to be loaded before it can be used.

Examples

@xmldef struct DocumentStatus
    exists."status/@exists"::Bool
    status."status"::String
    url."status/@url"::Union{String, Nothing} = nothing
    age."status/@age"::Int
end

RestClient.@formdef — Macro
@formdef struct ... end

Define a struct that serialises as FormFormat. Supports the name."form_key"::Type syntax for remapping a field's form name. A field typed Union{…, Nothing} defaults to nothing, and is left out of the form when nothing. A collection (a Vector, Tuple, or Set) is sent as one field per element, as in tags=a&tags=b.

Example

@formdef struct Login
    username::String
    password::String
    remember_me."remember-me"::Bool = false
end

RestClient.@multipartdef — Macro
@multipartdef struct ... end

Define a struct that serialises as MultipartFormat. Each field is encoded with its type's own dataformat: @jsondef fields become JSON parts, Vector{UInt8} / IO fields become octet-stream file parts, and others become text parts. A MultipartFile field sets its file's name and Content-Type. A collection without a format of its own, such as a Vector{String} or a Vector{Vector{UInt8}}, is sent as one part per element under the field's name. As with @formdef, a field typed Union{…, Nothing} defaults to nothing, and is left out when nothing.

Example

@multipartdef struct Upload
    file::Vector{UInt8}
    metadata::Metadata    # `@jsondef struct Metadata ... end`
    note::Union{String, Nothing}
end

RestClient.Request — Type
Request{kind, E<:AbstractEndpoint}

A request to an API endpoint, with a specific configuration.

This is the complete set of information required to make a kind HTTP request to an endpoint E. This consists of the request configuration and target endpoint itself. The kind and endpoint::E are put as type parameters so that they may participate in method dispatch.

RestClient.RequestConfig — Type
RequestConfig(baseurl::String; key, ratelimit, timeout, cache)
RequestConfig(config::RequestConfig; baseurl, key, ratelimit, timeout, cache)

The general configuration for a request to the API, not tied to any specific endpoint.

At a minimum, this holds the base URL of the API, and the pacing state its requests share.

Other fields are optional, but may be useful for changing the way requests are performed or handling authentication. The following additional fields can be provided as keyword arguments:

  • key::Union{Nothing, String}: The secret used to authenticate requests. How it is presented on the wire is declared by endpoints. It is shown as ***** in the REPL and in errors and debug output, but repr and string give it in full.
  • ratelimit::RateLimit: How fast requests may be sent, see RateLimit. Defaults to no limit, though a response's rate-limit headers are always kept to.
  • timeout::Float64: The longest a request may take, in seconds, or for a Stream, the longest it may go without receiving data. Defaults to Inf, no limit, so a stream waits as long as it takes. Even so, a request that sends and receives nothing for 20 seconds (or timeout, if longer) is abandoned. Either limit raises a TransportError.
  • cache::Bool: Whether to cache the response, using lifetime information from standard HTTP response headers. Defaults to true. Responses are kept on disk in the user's cache directory (on Linux, ~/.cache/julia/restclient/), so they last between sessions; entries past their lifetime are cleared as Julia exits, and deleting that folder clears the whole cache.

The second form derives a config from config, with any of its fields overridden, such as another key or host. It shares config's pacing, so requests through either wait for each other.

See also: @globalconfig, Request.

Examples

julia> RequestConfig("https://api.example.com", timeout = 5, cache = false)
RequestConfig("https://api.example.com"; timeout = 5.0, cache = false)

julia> config = RequestConfig("https://api.example.com", key = ENV["API_SECRET_KEY"])
RequestConfig("https://api.example.com"; key = "*****", cache = true)

julia> RequestConfig(config, key = nothing, timeout = 300)
RequestConfig("https://api.example.com"; timeout = 300.0, cache = true)
source
RestClient.RateLimit — Type
RateLimit(rate::Real = Inf; burst::Integer = 1, inflight::Integer = typemax(Int))

How fast the requests sharing a RequestConfig may be sent: on average at most rate a second, up to burst of them at once, with no more than inflight awaiting a response at a time (a Stream until its response begins). A request that would exceed the limit waits until it may be sent.

Give a limit published over a window, such as "100 a minute", as its rate, RateLimit(100/60). A burst of the window's whole count would let up to twice that through in some windows.

See also: nextallowed, for limits a response reports.

Examples

RequestConfig("https://export.arxiv.org/api"; ratelimit = RateLimit(1/3))
RequestConfig("https://lichess.org/api"; ratelimit = RateLimit(inflight = 1))
source
RestClient.AbstractEndpoint — Type
AbstractEndpoint

Abstract supertype for API endpoints.

What a request to an endpoint returns follows from its responsetype: a ListResponse is wrapped in a List, a SingleResponse gives its contents, and a Stream is read incrementally.

To share behaviour across an API's endpoints (auth, validation, logging), define an abstract subtype for the API and give it the shared methods. Headers and parameters for the whole API are defined for the type, and add to each endpoint's own (see headers). Other methods, such as validate, apply unless an endpoint has its own, and those @endpoint generates (urlpath, parameters, payload) always are.

Interface

urlpath([config::RequestConfig], endpoint::AbstractEndpoint) -> String
headers([config::RequestConfig], endpoint::AbstractEndpoint) -> Vector{Pair{String, String}}
parameters([config::RequestConfig], endpoint::AbstractEndpoint) -> Vector{Pair{String, String}}
responsetype(endpoint::AbstractEndpoint) -> Type
validate([config::RequestConfig], endpoint::AbstractEndpoint) -> Union{Nothing, Bool, AbstractString, AbstractVector{<:AbstractString}}
postprocess([response], request::Request, data) -> Any

All of these functions but urlpath have default implementations.

See also: Request, dataformat, interpretresponse.

RestClient.List — Type
List{T, E<:AbstractEndpoint, R<:Request, D}

A page of T items, from an R request to an E endpoint whose response was read as a D (a ListResponse).

A List iterates and indexes as its items. Its fields are request, items, data (the response's body as read, such as for a total count), response (its status and headers), and page, its number among the pages nextpage has fetched. With Tables.jl loaded, a List of structs is a table, one row per item.

Headers

The headers of a Response, looked up by name in any case.

headers[name] gives the first value of name, raising a KeyError if there is none, and get(headers, name, default) gives default instead. Iterating gives every name => value pair in order, with names in lower case, so a header sent more than once, such as Link, appears each time.

Errors

A failed perform raises one of these. A request that does not validate raises a MalformedRequest before anything is sent; an unsuccessful HTTP status raises a ResponseError carrying the server's response body; and a successful response that can't be read as the endpoint's result type (malformed JSON, a missing key) raises a MalformedResponse naming the request and holding the body. A failure in transit (DNS, connection refused, TLS, exceeding the total timeout, or going silent for too long) raises a TransportError saying which, with any auth secrets hidden from its URL.

RestClient.ResponseError — Type
ResponseError <: Exception

An exception type for requests that complete but return an unsuccessful HTTP status (outside 200:299).

Unlike a bare transport failure, the server's response is available: response holds the status and headers, and body holds the raw response body, which APIs routinely use to explain why a request failed.

See also: perform, Request.

Examples

try
    search(query = "...")
catch err
    err isa ResponseError{<:Request{<:Any, <:MyAPIEndpoint}} || rethrow()
    throw(RestClient.interpretresponse(err.body, JSONFormat(), MyAPIError))
end

RestClient.MalformedRequest — Type
MalformedRequest <: Exception

An exception type for requests that fail validation.

RestClient.MalformedResponse — Type
MalformedResponse <: Exception

An exception type for successful responses that cannot be read as the expected type, such as malformed JSON or a missing required key.

request and response say where the response came from, type is what it was being read as, body holds the bytes that failed (for a Stream, the frame's payload), and error is the underlying exception.

See also: perform, interpretresponse.

source
RestClient.TransportError — Type
TransportError <: Exception

An exception type for requests that fail without a complete response.

request is the request that failed, url where it was sent (with secrets hidden), message the transport's own account of the failure, and reason what kind of failure it was:

  • :resolve: the host could not be found;
  • :connect: the host could not be connected to;
  • :tls: the secure connection failed, such as over an invalid certificate;
  • :timeout: the request took longer than its config's timeout;
  • :silence: the request went too long without receiving data;
  • :dropped: the connection closed before the response was complete;
  • :redirects: the server redirected too many times;
  • :other: anything else.

See also: perform, RequestConfig.

RestClient.Stream — Type
Stream{T, F}

A lazily consumed stream of elements of type T, framed by F (:SSE, the default, or :NDJSON). Like a List, it is chosen through an endpoint's output type.

Iterating it blocks until the next element has arrived and been decoded. Any task may close it, which ends iteration without an error (see the manual on cancellation), and a stream that is dropped before it is drained is reclaimed by its finalizer.

See also: isstreamend.

RestClient.isstreamend — Function
isstreamend(endpoint::AbstractEndpoint, frame) -> Bool

Whether frame ends the stream from endpoint, without reaching the consumer. The default is false, ending a stream only when the connection closes; an API that marks its end in band needs a method checking the frame.

Each frame is checked twice: before decoding, with its payload still bytes (as an SSEvent{Vector{UInt8}}), and after, as the stream's element (an SSEvent{T}, or a T). A method sees whichever its type matches, so one that reads a decoded field types the payload:

RestClient.isstreamend(::ChatEndpoint, fr::SSEvent{<:AbstractVector{UInt8}}) = fr.data == codeunits("[DONE]")
RestClient.isstreamend(::MessagesEndpoint, fr::SSEvent) = fr.event == "message_stop"
RestClient.isstreamend(changes::ChangesEndpoint, fr::SSEvent{<:Change}) = fr.data.time >= changes.until
source
RestClient.isstreamskip — Function
isstreamskip(endpoint::AbstractEndpoint, frame) -> Bool

Whether frame is left out of the stream from endpoint, such as a keep-alive or monitoring event. Like isstreamend, it is checked before and after decoding, so a frame that wouldn't decode can be skipped by its raw form. The default is false.

RestClient.validate — Function
validate([config::RequestConfig], endpoint::AbstractEndpoint) ->
    Union{Nothing, Bool, AbstractString, AbstractVector{<:AbstractString}}

Check if the request to endpoint according to config is valid.

The return value determines whether the request proceeds and, if not, what problem to report:

  • nothing or String[] means the request is valid and should proceed
  • a string or vector of strings means the request is invalid and should be aborted, with the string(s) as the reason(s)
  • true or false means valid or invalid, without a reason

This is also the appropriate place to emit warnings about non-critical potential issues with the request, using @warn or @debug.

RestClient.perform — Function
perform(req::Request{kind}) -> Any

Validate and perform the request req, and return the result.

The kind of the request is its HTTP method, one of: get, post, put, patch, delete, head, options, query. The result depends on the endpoint: the response parsed as its responsetype (read incrementally, for a Stream), passed through postprocess. A :head request's result is whether the resource exists: true on success, false on 404 or 410.

Redirects are followed, a 303 (See Other) with a GET as it asks. Every request identifies itself as User-Agent: RestClient.jl/<version> unless the endpoint's headers give their own.

Retries and rate limits

Requests sharing a config are sent no faster than its RateLimit, and wait out any deadline a response sets: one its headers give (a Retry-After, or an X-RateLimit-Reset with X-RateLimit-Remaining: 0), or nextallowed does. Responses served from the cache are not held back.

A 429 is retried at its deadline, or failing that after an exponential backoff (about 0.5, 1, 2 then 4 seconds, with jitter). A 403 or 503 is retried when its headers give a deadline, and any other unsuccessful response when nextallowed does. A gateway failure (502, 503 or 504) is retried after the backoff, for methods safe to repeat (not POST or PATCH). A request is attempted at most five times.

A wait longer than the request's timeout isn't waited: a retry is raised instead, and a request is sent anyway. With the default timeout = Inf, a wait can be long (until an hourly quota resets, say), so set a timeout to bound it.

Errors

  • MalformedRequest if the request fails validation.
  • ResponseError if the server responds with an unsuccessful status, once any retries are spent.
  • MalformedResponse if a successful response can't be read as the endpoint's responsetype.
  • ArgumentError if kind is not a supported HTTP method.

See also: Request.

RestClient.authscheme — Function
authscheme(endpoint::AbstractEndpoint) -> AuthScheme

Return how endpoint authenticates: the AuthScheme describing where the request's secret (config.key) is placed on the wire. The library applies it to key automatically, so a standard scheme needs no headers method.

The default is the scheme given by @globalconfig auth= in the endpoint type's module, else NoAuth. Alternatively, declare a scheme once per API on a shared endpoint supertype:

RestClient.authscheme(::MyAPIEndpoint) = BearerAuth()          # Authorization: Bearer <key>
RestClient.authscheme(::OtherEndpoint) = HeaderAuth("X-API-Key")

For a scheme the provided ones do not cover, define a new AuthScheme; for one that can't be expressed as a header or query parameter (request signing, OAuth flows), read config.key in a headers method directly instead.

Part of the AbstractEndpoint interface.

RestClient.authpolicy — Function
authpolicy(endpoint::AbstractEndpoint) -> Symbol

How endpoint uses authentication, one of:

  • :off — never send auth (the default);
  • :optional — apply the authscheme to the request's key if one is set, but do not require it;
  • :required — apply it, and reject a request whose config.key is nothing during validation, before sending, rather than relying on the server to return 401.

The default is the policy given by @globalconfig auth= in the endpoint type's module (:off without one), looked up when a request is made. The @endpoint macro overrides it per endpoint with an :auth (required), :authoption (optional), or :noauth (off) marker.

Authentication

An endpoint declares which scheme it authenticates with via an authscheme method, and whether a key is off/optional/required via authpolicy; the secret itself is the RequestConfig's key. Both are usually set in one place with @globalconfig's auth= option.

RestClient.AuthScheme — Type
AuthScheme

Supertype for authentication schemes, which describe how an API expects its secret: in which header or query parameter, and in what form. A scheme never holds the secret itself, which is the key of a RequestConfig. Declare an endpoint's scheme with authscheme, and every request applies it to key.

The provided schemes are BearerAuth, BasicAuth, HeaderAuth, QueryAuth, and NoAuth (the default).

For any other header or query parameter scheme, define a subtype with an authheaders or authparams method. A scheme's header or parameter is hidden in debug output and errors, while a key an endpoint adds itself (in its own headers, parameters, or urlpath) is not.

struct TokenAuth <: AuthScheme end
RestClient.authheaders(::TokenAuth, key::String) = "Authorization" => "Token $key"

RestClient.postprocess — Function
postprocess([response], request::Request, data) -> Any

Post-process the data returned by the request, by default returning it as-is.

data is the response body already read as the endpoint's responsetype: reading happens first, and a body that can't be read raises a MalformedResponse without reaching postprocess. An error status raises a ResponseError before either. To raise an error an API reports inside a successful response, throw it here.

The result is then restructured: a ListResponse is wrapped in a List, and a SingleResponse gives its contents. So a method may check or unwrap the data, and a ListResponse it returns is still paged.

The three-argument form also sees the response, with its status and headers; by default it calls the two-argument form.

Pagination interface

RestClient.nextpage — Function
nextpage(list::List) -> Union{List, Nothing}
nextpage([response], endpoint::AbstractEndpoint, data) -> Union{AbstractEndpoint, AbstractString, Nothing}

Fetch the page after list, or return nothing if it is the last.

An endpoint gives where its next page is with the second form, from the data of the page before (its ListResponse, after postprocess), and in the three-argument form its response too: the next page's endpoint, its URL, or nothing for none. Without such a method, the page the response's Link: <…>; rel="next" header gives is fetched (RFC 8288). A URL may be absolute or start with /, and must lie under the API's baseurl.

The endpoint is that of the request for the page before, or for a page reached by URL, of the first page. Pages are numbered on from the first (see thispagenumber), and pagecount may give their total.

Examples

# A page number, until the response says there are no more
RestClient.thispagenumber(search::SearchEndpoint) = search.page
RestClient.nextpage(search::SearchEndpoint, results::SearchResults) =
    if results.has_more SearchEndpoint(search; page = search.page + 1) end

# A cursor
RestClient.nextpage(works::WorksEndpoint, page::WorksPage) =
    if !isnothing(page.next_cursor) WorksEndpoint(works; cursor = page.next_cursor) end

# The next page's URL, given in the response
RestClient.nextpage(::ResourcesEndpoint, page::ResourcePage) = page.next

Rate limit interface

RestClient.nextallowed — Function
nextallowed(endpoint::AbstractEndpoint, response::Response) -> Union{Real, Nothing}

Return when the API next allows a request after response to a request to endpoint, in seconds from now or as a Unix time (a time() value), or nothing to set no time. A time worth more than a year of seconds is taken as a Unix time.

Each response from the network is given to this, and the requests sharing its config wait until the later of this and the time its rate-limit headers set (Retry-After, or X-RateLimit-Reset with X-RateLimit-Remaining: 0), so a method can only lengthen the wait. An unsuccessful response with a time is retried then, and with Inf is raised without a retry. By default nothing.

See also: RateLimit, for limits known ahead of time.

Examples

# A full minute's pause after any 429
RestClient.nextallowed(::LichessEndpoint, response) = if response.status == 429 60 end

Content formatting

Each type a request sends or receives has a format: its own, from @jsondef, @xmldef, @formdef or a dataformat method, or else its API's, which is raw text or bytes unless @globalconfig's format option says otherwise (e.g. format = :json for an API whose plain values, like a Vector{String}, are JSON). A single endpoint can still differ: in a JSON API, a text/plain one declares RestClient.dataformat(::ThatEndpoint, ::Type{String}) = RawFormat().

RestClient.AbstractFormat — Type
AbstractFormat

Abstract supertype for response formats.

Typically, you will want to create a singleton subtype and then implement the following methods for it:

  • An interpretresponse method so a response in that format can be parsed/interpreted as a specific type.
  • A writepayload method so data can be sent in that format.
  • A mimetype method so that appropriate headers can be set when sending or receiving data in this format.

See also: RawFormat, JSONFormat.

source
